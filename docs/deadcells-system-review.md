# 星跃远征：基于本地《死亡细胞》静态分析的系统优化方案

审阅日期：2026-11-17。对象是 `F:/开发/rea-deadcells` 内导出的配置、HashLink 反汇编，以及当前星跃 v5 本地试炼代码。本轮完成审阅与方案，没有修改游戏玩法，也没有复制《死亡细胞》的程序或美术资源进游戏。

## 结论与证据边界

优先改造动作执行与怪物攻击，再改地图与成长。现有星跃已经有闪避伤害、追击、精准格挡和三种武器强化，但还缺少统一的动作阶段、攻击描述和房间约束。继续增加伤害倍率或特效，不能解决这些基础问题。

本地资料含 141 条武器配置、350 段攻击、135 条敌人配置、112 条关卡和 2,191 条房间配置。反汇编可检索函数与分支，但不是完整恢复的 Haxe 源码；原始时间、坐标和伤害字段不能直接当作星跃的运行时参数。以下严格区分静态事实和本项目设计建议。

## 1. 战斗：把计时器升级成动作状态机

**读取到的证据**

- [武器配置](../../rea-deadcells/tables/weapon.json)：每段攻击有 `charge`、`hitFrame`、`lockCtrlAfter`、`area`、`breachBonus`、`animId`、`animSpd` 等字段；部分有 `earlyCombo`。
- [f1854](../../rea-deadcells/reports/disassembly/1854.txt) 实际读取 `earlyCombo` 和 `lockCtrlAfter`；[f1869](../../rea-deadcells/reports/disassembly/1869.txt) 根据武器取消限制、盾类型和蓄力状态分支，并存在动画停止与技能中断调用。这证明取消与连招有独立规则，不能概括为“所有后摇随时取消”。
- [f2039](../../rea-deadcells/reports/disassembly/2039.txt) 在特定单向平台保护条件下拒绝攻击，再调用通用受击判断；[f2018](../../rea-deadcells/reports/disassembly/2018.txt) 将精准格挡分发成独立信号。

**星跃现状**

`assets/game-core.js` 的 `updateAttacks()` 在 `attackTimer > 0` 时就进行刀的碰撞判定；动作动画与碰撞生效时刻没有共同的命中标记。`assets/souls-combat.js` 用统一时间阈值控制闪避接攻击，并给全部普攻配置精力消耗。当前精准格挡处理只收到伤害与来源横坐标，无法严格区分攻击类型、攻击所属敌人和是否允许弹反。

**建议实施**

1. 明确 `startup → active → recovery` 三段动作，输入请求只进入队列，状态机决定执行。碰撞仅在有效阶段开启，同一次攻击用 `attackId + targetId` 去重。
2. 把攻击动画、刀光、音效和判定绑定同一条动作时间线。命中判定随固定模拟步进触发，渲染帧率变化不改变伤害。
3. 按武器和招式配置取消窗口：轻刀收招可接闪避；重击生效前保留承诺；闪避后半段可接追击。取消旧动作时同时关闭旧命中框，避免取消后仍出伤害。
4. 用 `AttackContext` 统一受击：来源实体、攻击 ID、类型、方向、伤害、冲击力、可格挡、可精准格挡、是否穿透。精准格挡只影响该次攻击及其所属敌人。
5. 保留魂游精力系统，但先试调普攻低消耗、闪避和防御高消耗。现在三类动作共同争夺精力，容易出现持续攻击后只能等待恢复的节奏；这需要试玩比较，不应声称某个新数值天然更好。

下面是星跃拟采用的新结构示意，不是反编译出的原代码：

```js
{
  id: 'jadeBlade.light1',
  phases: { startup: 0.07, active: 0.06, recovery: 0.13 },
  hitbox: { offsetX: 18, offsetY: -4, width: 48, height: 34 },
  cancel: { dodgeAfter: 0.15, comboAfter: 0.18 },
  damageScale: 1,
  impact: { stagger: 12, hitstop: 0.03 },
  animation: 'blade.light1'
}
```

示意时间需要结合现有素材帧数和手机实测校准，不是《死亡细胞》的还原参数。

**验收**：提前按下的下一击不会丢失；有效帧外没有伤害；取消后没有残留判定；30/60/120 Hz 渲染下，同一输入回放伤害结果一致；Boss 的可格挡攻击有可辨识提示。

## 2. 地图：房间连接图 + 手工模板 + 可达性验证

**读取到的证据**

- [f31818](../../rea-deadcells/reports/disassembly/31818.txt) 包含 `generateGraph`、`generateMaps` 和 `buildData` 等调用，生成过程存在结果检查及重试路径。
- [f31846](../../rea-deadcells/reports/disassembly/31846.txt) 可见种子随机打乱候选、读取生成标记等操作；[f31847](../../rea-deadcells/reports/disassembly/31847.txt) 根据节点连接约束和模板连接方向/垂直属性分支。
- [关卡表](../../rea-deadcells/tables/level.json) 分开配置生物群系、怪物密度、奖励、后续区域；[房间表](../../rea-deadcells/tables/room.json) 有类型与标记。提取的 BTMX 尚未解码为普通 Tiled XML，不能直接当作可用地图模板。

**星跃现状**

`mA()` 从固定平台数组选路线；`enrichRoom()` 在其上微调高度、加桥、宝箱台和补给。可以带来局部差异，但仍是长条关卡。现有确定性与边界测试不等于已验证整张图可通行。

**建议实施**

- 先做一张区域图：入口 → 两个战斗房 → 休整/强化 → 精英 → 出口；分出宝物或高风险支路，并允许回环。
- 每个模板声明门位、高差、平台导航点、怪物槽位、奖励槽位、安全出生区；先准备 12 个可反复组合的原创小房间。
- 连接图决定节奏，模板决定跳跃与战斗体验，区域皮肤决定画面。三者分别管理，避免地图只是换背景。
- 用角色真实移动、短跳/长跳/二段跳能力构建导航边；校验入口到出口、必要奖励、返程路径与出生安全。有限重试失败后使用已验证的保底布局。
- 地形、敌人、奖励、装饰分用独立的派生种子，避免新增一根草改变敌人掉落。

**验收**：批量 1,000 个种子验证必要节点可达、没有门位堵塞或无法返程的必要路线；同种子同规则可复现；主路奖励预算固定，支路奖励体现风险。

## 3. 升级：属性成长、玩法强化与补给分别管理

**读取到的证据**

- [f1959](../../rea-deadcells/reports/disassembly/1959.txt) 分别统计 Tactic、Survival、Brutality 并更新对应 tier；[f1954](../../rea-deadcells/reports/disassembly/1954.txt) 调用生命缩放函数。
- [物品表](../../rea-deadcells/tables/item.json) 含 `tier1` 等字段；[词缀表](../../rea-deadcells/tables/affix.json) 含 `requiredTags`、`forbiddenTags`、`forbiddenAffixes`、`allowStacking`。
- [f484](../../rea-deadcells/reports/disassembly/484.txt) 可确认某个装备伤害加成子公式使用装备调整等级和属性加成计数。它不是完整最终伤害公式。
- [主角表](../../rea-deadcells/tables/hero.json) 有 rally 配置；[f1989](../../rea-deadcells/reports/disassembly/1989.txt) 分开存储生命和受边界限制的 rally 值。完整回血触发、衰减和最终比例本轮未还原。

**星跃现状**

升级主要从通用增伤、攻速、多弹、生命、护盾等选项里抽取；升级回血、清房回血、地图补给、击杀回血已并存。若继续提高各处回血概率，会降低路线和防御决策的价值。

**建议实施**

- 先保留用户已经要求的升级回血，再统一统计各区的保证回复量和随机回复上限。
- 分为基础属性、改变打法的强化、武器词缀三层。可设计原创的「锋刃 / 灵术 / 守势」路线，装备按标签受益；不要硬搬成熟游戏的完整缩放曲线。
- 先实现三组能改变操作的选择：闪身追击、燃烧引爆、回轮接刀。强化池根据已有标签提高相关选项权重，同时保留转型出口。
- 词缀声明触发事件、适用标签、互斥关系与叠加上限。额外伤害事件带触发深度或递归限制，避免“爆炸触发爆炸”无限循环。
- 受伤后攻击回收部分生命可作为后续实验，不能直接把原始百分比套进现在的 5 点生命。若引入，需要更细的内部生命刻度、临时可回收池、过期规则和防无限刷取限制。

**验收**：无效强化不进池；同一触发链不会递归失控；回血不超上限；三种流派各有明确操作收益，而非只是不同颜色的加伤害。

## 4. 武器：每把武器有独立的目标与操作奖励

**读取到的证据**

武器表把连段、范围、冲击、动画与取消分开配置。物品表中 `BackStabber` 的描述明确写背击暴击；`StartBow` 有弹药与回收说明；`Boomerang` 配置自动返回与有限弹药。这里只将表述视为设计证据，没有据此宣称这些武器的完整运行时逻辑已经复原。

**星跃现状**

法杖和飞轮已增强，但三者仍共享较多的“三段后增强”节奏。继续把它们统一成第三击变大，差异仍有限。

**建议实施**

| 武器 | 应有的操作目标 | 原创条件奖励 | 主要代价 |
|---|---|---|---|
| 短刃 | 近身穿插、闪避后抢窗口 | 背击或精准反击后的追击强化 | 需要贴身，轻击破架势弱 |
| 法杖 | 标记与引爆、控制距离 | 连续命中积累灼印，再主动引爆 | 蓄力/施放承诺，短时间不能无限倾泻 |
| 飞轮 | 调整站位使去回程都命中 | 去程标记、回程强化；接回时获得下一轮加速 | 在场数量上限、需要等待回收或花代价提前召回 |

建议以条件奖励逐步替代部分纯随机暴击，让玩家知道“刚才为什么打得更好”。先把三把现有武器做出不同节奏，再增加武器数量。

**验收**：每把武器至少一个可主动追求的奖励条件；相同投入下能应对不同战斗房；大范围、爆发、破架势和安全距离不能全部集中在同一把武器上。

## 5. 怪物：从移动模型变成可读、可应对的攻击者

**读取到的证据**

- [怪物表](../../rea-deadcells/tables/mob.json) 同时描述技能与生成约束，含 `charge`、`hitFrame`、`coolDown`、`lockAiAfter`、`allowSameSkillNearby`、`maxPerRoom`、`maxPerPlatform`、`minPfSize` 等字段。字段存在不等于所有约束消费者已经还原。
- Zombie 的近战与跳扑有不同配置；[f21324](../../rea-deadcells/reports/disassembly/21324.txt) 能看到调用基础更新、检查冷却及进入跳扑处理的路径。不能把这个实例外推为所有敌人 AI。

**星跃现状**

普通敌人主要是追踪飞行、接近跳动、定时射击；接触伤害承担大量威胁。精英主要加生命和初始攻击频率。Boss 已有蓄力/恢复状态，可作为普通怪改造的起点。

**建议实施**

- 统一 `巡逻 → 发现 → 接近/站位 → 预警 → 出招 → 收招 → 失衡/死亡`，每种怪只替换决策和技能参数。
- 先做三种角色：近战压迫者、远程封线者、盾卫。玩家应分别用闪避抢位、切入打断、绕后/重击解决。
- 可格挡近战接触只在主动攻击有效阶段造成伤害；尖刺怪或危险飞行体可保留接触伤害，但轮廓要明确。
- 预警阶段允许有限瞄准，出招后停止无限追踪；给玩家能预判的招式承诺。
- 遭遇战限制同时出手数量，按平台面积和高差投放敌人，避免多名远程怪同帧无预警射击。
- 精英优先增加一个明确行为变体，例如延迟二连击或有预警的区域控制，再增加血量。
- 精准格挡削减攻击者架势，是否直接进入失衡由技能与剩余架势决定，避免所有 Boss 技能都被一次格挡固定中断。

**验收**：每种敌人有不同反制方法；预警到命中时刻稳定；受击/死亡后旧招式不能继续命中；落差或墙体阻挡时不会隔墙无提示攻击。

## 6. 美术：统一像素与光色，比继续升画布分辨率更重要

**读取到的证据**

- [biome 表](../../rea-deadcells/tables/biome.json) 分别配置 `ambient`、`fog`、`celShadow`、光色、多个层和各层的 `lightType`、`lightDepth`。
- [f2948](../../rea-deadcells/reports/disassembly/2948.txt) 实际读取环境光、雾、阴影和分层配置；[f2949](../../rea-deadcells/reports/disassembly/2949.txt) 读取相机雾配置。
- [lightConf](../../rea-deadcells/tables/lightConf.json) 单独配置灯光半径、衰减、强度等。[人物动画轨迹](../../rea-deadcells/extracted/atlas/beheaded_tracks.json) 存在头部、手部与道具等逐帧轨迹，说明可以研究挂点随动作变化；不能仅凭此文件完整断言原游戏制作流程。

**星跃现状**

当前 Canvas 已有高清输出、视差和授权像素素材，但素材来自多套资源。高清输出能减少显示模糊，不会自动统一素材的像素尺度、轮廓、光源和动作风格。

**建议实施**

- 先建立「星跃美术规格表」：人物身高、场景 tile 单位、描边层级、每个实体的逻辑像素尺寸、主要动画帧数与接地点。
- 保留东方机械遗迹方向：玉绿为主角/友方能量，朱红为高威胁敌招，旧金为精准格挡与重要奖励。颜色之外叠加不同形状提示，避免只靠颜色辨识攻击。
- 背景降低对比与细节密度；可站平台边缘、角色轮廓与攻击有效区域更清晰。装饰、雾和前景树不应遮住关键判定。
- 武器挂点、发射点和脚底位置随动画帧对齐，避免贴图在动而火球从固定位置凭空出现。
- 先用低分辨率光照遮罩、预绘光晕和分层调色实现灯光；Canvas 2D 路线先不承担完整法线与实时阴影管线。若后续迁移 WebGL，再评估法线贴图。
- 手机提供特效密度与分辨率档位；逻辑坐标保持一致，不能通过改变碰撞大小节省渲染。

**验收**：截图缩小后仍能识别玩家、敌招和落脚点；不同场景的角色尺寸和光源一致；中档手机上保留关键攻击提示，优先减少环境粒子和远景效果。

## 实施顺序与代码落点

| 阶段 | 实施内容 | 当前代码落点 | 先不扩张的内容 |
|---|---|---|---|
| 第一阶段 | 动作状态机、统一攻击数据、三把武器独立动作表、基础怪预警与收招 | `game-core.js` 的 `attack/updateAttacks/updateEnemies`；将 `souls-combat.js` 的原型补丁逐步收敛成显式模块 | 新武器数量、大量新词缀 |
| 第二阶段 | 房间连接图、模板门位、遭遇战槽位、真实可达性检查 | 拆分 `mA` 与 `enrichRoom`，增加 `map/room-templates/encounters` | 无约束大地图、全随机地形 |
| 第三阶段 | 升级标签、三组流派、奖励预算、素材规范与分层光色 | `offerUpgrade/chooseUpgrade`；`souls-presentation.js` 与素材导入表 | 大规模永久数值成长、完整光照引擎 |

先做一个包含三种敌人、三把武器、一个精英与可选奖励支路的短区域，用同一段关卡反复比较操作反馈。基础动作和反制成立后再扩展八境，返工成本更低。

本轮新补充的函数反汇编保存在 `rea-deadcells/reports/disassembly/`：1854、1855、1869、1883、1954、1956、1957、1958、1959、1989、2068、2948、2949、528。它们由现有解析脚本从本地字节码生成，没有修改游戏原文件。
